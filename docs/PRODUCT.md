# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

static HTML/CSS/JavaScript, delegated to the implementation agent for a lightweight Codespaces-friendly surface.

## Users

CSE students and open-source developers exploring fast, screen-driven game automation in a browser-based development environment.

## Product Purpose

Show and explain a modular gaming-bot framework that separates screen capture, semantic action choice, and keyboard actuation. Success means a visitor understands the architecture quickly and can run the simulator immediately.

## Positioning

The framework makes the see-think-act pipeline inspectable: deterministic pixel telemetry feeds a typed TypeSafe System One decision, while safety rules remain in ordinary code.

## Operating Context

The project is developed in GitHub Codespaces, where simulator mode is the reliable first-run experience and native mode requires an external graphical display and keyboard permissions.

## Capabilities and Constraints

The repository includes simulator mode, TypeSafe integration scaffolding, profile-driven detector/input settings, bounded state handoff, safety controls, preflight, JSONL telemetry, and tests. Native display/input and live API behavior require external hardware, permissions, and credentials.

## Brand Commitments

The name `system1-gamebot` and the eyes / brain / hands language are established project vocabulary. The landing page should be candid about simulator-first development and should not invent customers, benchmarks, or universal plug-and-play claims.

## Evidence on Hand

The working simulator, profile example, test suite, and runtime telemetry are real repository artifacts. No customer logos, testimonials, or native benchmark evidence are available.

## Product Principles

- Keep the pipeline visible.
- Let deterministic code own safety.
- Make the simulator the fastest proof.
- Label measured behavior honestly.
- Keep game-specific calibration explicit.
